# 实时输出 TUI 增强设计

## 目标与边界

Issue #16 的核心不是把黑色文本块“换皮”，而是保住不同 agent 的事件语义。实时输出继续复用 #3 的磁盘历史 + SSE 增量链路，不另建任务状态源；停止、重连、完成后历史选择逻辑不变。token 用量只作为流中可得的软事实展示，不估算、不阻断任务。

## 方案比较

1. 前端按 emoji/文本猜测类型：改动小，但丢失的结构无法在重连后恢复，不能可靠区分 agent，拒绝。
2. 为 Codex 和 Claude 各写一套完整终端组件：短期直观，但 detach、滚动、计时和历史逻辑会重复并漂移，拒绝。
3. Host 使用两套解析适配器，归一为一个结构化日志协议；前端复用一个终端组件：解析差异独立，展示基础设施共享，采用。

## 数据流

Codex 适配器识别 `command_execution`、`reasoning`、`token_count`；Claude 适配器识别 `tool_use`、`thinking` 及 message/result usage。归一事件包含 `source`、`agent`、`kind`、`text` 和可选 `usage`，以带版本前缀的编码行写入现有日志。`/history` 同时返回兼容的纯文本 `lines` 和结构化 `events`；SSE 增量携带同一 event。旧日志没有结构时按 `[clickvibe]` 前缀识别系统行，其余作为普通 agent 文本。

## UI 与生命周期

终端头部只在任务运行时显示走秒时长，token 事件存在时才显示 usage。正文按系统提示、命令、命令输出、思考、工具和消息分色，并随事件自动滚动。detach 只是把同一组件通过 portal 移到高层浮窗：桌面保留边距，手机小于 768px 时占满屏幕；Esc 或按钮收回。任务结束后实时区收起为“历史输出”折叠项，内容继续来自同一磁盘日志，不复制状态。

## 验证

单元测试覆盖两类 agent 的独有事件、嵌套 token schema、结构化日志新旧兼容、时长格式；路由测试覆盖 Host 重启后的结构恢复。最后运行完整测试、类型检查与构建，并在可用的宿主页面中检查桌面/手机 detach、滚动和收回行为。
