# Issue #85 详情页长内容设计

## 目标与取舍

详情页的依赖图、GitHub 时间线和交付流水统一使用一个轻量折叠容器。容器提供可点击且可吸顶的标题、明确的展开状态和块内滚动区域，不引入组件库或全局状态。依赖图默认展开，便于先看到开发门槛；GitHub 时间线默认折叠，减少低频关联事件占用；交付流水默认展开，保留当前开发阶段的可见性。

折叠状态写入浏览器 `localStorage`，键由详情 URL 与块类型组成。这样重新打开同一详情会恢复用户选择，不会让一个 issue 的选择污染其他 issue。存储不可用、内容损坏或写入失败时静默回退到默认态，不能阻断详情渲染。

## 组件与滚动

`CollapsibleSection` 只负责折叠交互和持久化，不理解业务数据。标题按钮暴露 `aria-expanded` 和关联内容 id；折叠时不渲染内容。标题使用 `position: sticky`，当用户在块内浏览时保留折叠入口。

展开内容限制最大高度并使用 `overflow: auto`、`overscroll-behavior: contain`。依赖图、GitHub 时间线和交付流水因此各自形成受控滚动区，不会仅因条目很多而持续拉长详情页，也不会在到达滚动边界时强制把滚动传给外层详情。

## 验证

纯逻辑测试覆盖存储读取、非法值回退和写入失败；组件静态渲染测试覆盖默认展开/折叠及无障碍属性；结构测试确认三个目标块都接入稳定键；样式测试锁定吸顶标题、最大高度、内部滚动和滚动链隔离。最后执行 typecheck、build、test、coverage、lint、format、size 和 layer 门禁，并以浏览器截图人工检查典型长内容。
