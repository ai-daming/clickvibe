# 各阶段统一需求快照提示词设计

## 目标

开发、Review、恢复开发与返工不再依赖 Agent 自行访问 GitHub。每次阶段启动都获得结构一致的提示词，内含当前 Issue 正文、`updatedAt`、相关评论、执行状态、阶段要求和信任边界。

## 结构

集中式 prompt builder 固定输出四段：需求快照、当前状态、要求与输出格式、信任边界。各阶段只提供自己的状态和要求：Review 注入 PR、commit 与 diff base；resume 保留精确会话语义，但明确记忆与快照冲突时以快照为准；rework 额外注入 Review 意见。

## 快照与降级

阶段启动时优先刷新 Issue，并在有关联 PR 时补充 PR 评论。刷新成功后把完整快照持久化到 workflow；刷新失败只能回退已有完整快照，并在提示词中标注“可能过期”。旧 workflow 若既无法刷新又没有持久化快照，则拒绝启动，避免退化成只有 URL 的提示词。

开发授权仍绑定用户确认的精确快照。启动前再次在线读取到不同内容时，旧授权失效并要求重新确认；网络不可用时使用已确认快照启动，同时立即持久化并标注可能过期。

## Review 意见

在线时从最新的 `== Review Meta ==` PR/Issue 评论中选择正文并原样拼接，不解析 Meta 字段。评论不可用时，依次回退最新本地 Review event 和当前本地 verdict。精确 resume 与 stale-session 后的全新会话使用同一份阶段启动快照与意见，避免回退时丢上下文。

## 验证

纯函数测试覆盖四阶段统一结构、`updatedAt` 锚定、信任边界、过期标记和意见降级。路由集成测试覆盖 Issue 在确认后变化、精确 resume 与全新会话回退、PR Review Meta 优先、离线持久化快照以及 Review 的 PR/commit 信息。最终门禁为全量测试、类型检查、构建和 `git diff --check`。
