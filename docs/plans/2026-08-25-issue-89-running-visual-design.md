# Issue #89 运行中视觉统一返工设计

## 修复轮母题与不变量

前两轮都以 `origin/main` 上既有提交作为交付 SHA，实际 diff 为零。这不是 UI
实现缺陷，而是交付事实与任务声明脱节。后续交付必须满足：HEAD 是当前分支相对
启动基线产生的真实提交，且 Dev Meta 的提交数与文件统计能由 git diff 回读验证；
零 diff 不得声明「已完成」或「已修复」。流程层的自动门禁应另行修复，不能混入
本 UI PR。

运行态事实继续由 #111 / PR #114 的三态所有权模型唯一提供。客户端只消费
`runStartedAt`，不得从 task id、历史或缓存自行推断任务仍在运行。

## 相对 #87 的增量

#87 已统一 `HH:MM:SS` 格式和 `RunningDuration` 组件，但终端头仍在组件外单独
拼装圆点，详情和列表没有相同的运行视觉标识。#89 的增量是把运行圆点收进
`RunningDuration`：三处都由同一 DOM 和同一语义类渲染圆点与时长。

详情和列表保留「正在运行 · 已运行 HH:MM:SS」，终端头在已有 `LIVE` 上下文中
保留紧凑的 `HH:MM:SS`；紧凑模式的可访问名称仍完整表达运行状态。圆点在普通
面板使用 DSH success token，在固定暗色终端使用对应的固定绿色，排版继承各自
上下文。不增加动画，避免引入 reduced-motion 新债务。

## 验证

- 组件测试锁定共享圆点、完整文案和紧凑模式可访问名称。
- 源码契约测试锁定终端不再拥有独立圆点。
- 样式测试锁定普通面板与固定暗色终端的同义运行色。
- 用生产组件与生产 CSS 的隔离验收页同时观察列表、详情和终端头；合入后再由
  实际 DSH 宿主复核。
