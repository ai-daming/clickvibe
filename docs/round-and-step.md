# 轮(round)与步(step)

ClickVibe 的交付流水线里有两个容易混淆的计数概念:**轮**和**步**。它们服务不同的目的,也显示在流水线的不同位置。

## 轮(round):开发 → Review 的一个闭环

- **定义**:一次"开发 → Review"的完整循环。第 1 轮 = 第一次开发 + 第一次 Review。
- **推进规则**:
  - Review 通过 → 闭环完成,流水线走向合并;
  - Review 未通过(附问题清单)→ 自动打回开发,进入第 2 轮(再开发 → 再 Review),循环直到通过或轮次上限耗尽。
- **谁在用**:交付事件(开发 / Review / 返工 / 恢复)上的"第 N 轮"是**全历史累计**的轮次号,重启自动跑也不会清零重号,保证事件可追溯、可对账。
- **状态字段**:
  - 交付事件轮次 = `deriveEventRound(events)` = 历史 Review 判定数 + 1(如"第 1 轮"是第一次开发);
  - `autoRun.rounds` = **本次自动跑内**已产出的 Review 判定数,用于轮次上限(`maxRounds`):返工轮数达到上限即 `rounds-exhausted` 暂停。

## 步(step):自动流水线推进的动作计数

- **定义**:自动流水线每**触发一个自动动作** = 推进一步。动作包括:启动开发 / 恢复开发(resume)/ 启动 Review / 返工 / 同步 / 建 PR / 合并 / 清理。
- **与轮的区别**:一步 ≠ 一轮。一次开发被中断重试 3 次(step 1→3),再推一次 Review(step 4),是 **4 步、但只完成了第 1 轮**。
- **谁在用**:
  - 时间线里"自动推进"事件显示"第 N 步"(启动/暂停/收敛是推进动作的节点,不是一轮,因此绝不显示"第 N 轮");
  - 卡片按钮显示"自动运行 · 第 X 步 · 已完成 Y/Z 轮",X 是推进步数,Y/Z 是已完成的轮数与轮次上限。
- **状态字段**:`autoRun.step` = 本次自动跑已触发的自动动作数。启动置 0,**每次重新启动自动跑都会归零**(它是"这一次自动跑怎么推进"的记录,和轮次上限无关)。

## 两者关系

| | 轮 round | 步 step |
|---|---|---|
| 语义 | 开发→Review 闭环 | 自动动作推进次数 |
| 计数时机 | Review 判定落地 +1 | 每次触发自动动作 +1 |
| 范围 | 交付事件:全历史累计;autoRun.rounds:本次自动跑内 | 仅本次自动跑内 |
| 清零 | 交付事件重启不清零;autoRun.rounds 重启归零 | 重启归零 |
| 上限控制 | maxRounds 只看 rounds(返工轮数) | step 不参与上限,仅展示进度 |
| 显示位置 | 开发/Review 事件"第 N 轮";卡片"已完成 Y/Z 轮" | 自动推进事件"第 N 步";卡片"第 X 步" |

## 典型时间线(例子)

开发重试 3 次再 Review 1 次、Review 未通过,进入第 2 轮:

```
自动推进 · 已启动
开发      · 第 1 轮 · Codex      (推进 1 步)
自动推进 · 第 2 步 · 已暂停:会话中断,重启后继续
自动推进 · 已启动
开发      · 第 1 轮 · Codex      (恢复开发,推进 3 步)
自动推进 · 第 4 步 · 已暂停:会话中断,重启后继续
自动推进 · 已启动
Review   · 第 1 轮 · Claude     (推进 5 步 …)
```

## 兼容性

- `autoRun.step` 是新增字段,旧状态缺失时按 0 起算(`isAutoRunState` 保持宽松校验,不拒绝旧状态);
- `WorkflowEvent.step` 是可选字段,旧事件缺失时时间线不显示步数;
- 对外契约(API 形状、review 结论格式、命令语法)不变。
