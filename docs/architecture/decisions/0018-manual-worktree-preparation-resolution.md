## 与既有设计的关系

本 ADR 补充 ADR-0016 §4.3/4.4 的人工出口及 §7.3 的结算证据：自动流程仍不得接管跨 runtime 的 dispatched；只有本规程允许维护者依据新的结束证据进行离线结算。它不把旧命令未知返回改写为已知成功，不变更 ADR-0017 的独立状态目录与升级规则。

这是设计变更，不是已验证可执行的操作手册，也不授权现场状态修改。合入后仍须实现、真实 Git/文件系统验证与 exact-head review；发布前完成下述门禁。

## 问题和建议

当前跨 runtime 的 dispatched 永久拒绝自动采用；新授权也不清除它。正确保护缺少人工出口。增加严格限定的离线人工结算规程，先以经过真实 Git/文件系统测试的操作文档交付，不新增常驻服务、HTTP API 或产品按钮。维护者执行前必须逐次审阅精确状态差异并授权。

不采用直接删除 preparation：这会让本次失败现场退回无凭证 legacy reuse 路径，丢失冻结 OID 与不重放约束。不采用在线 resolve 按钮：尚未能从宿主证明逃逸子进程已经结束，增加按钮不能补足结束证据。

## 1. 静止和证据

停止 DSH、禁用自动重启，停止所有可能写同一 Git common-dir 的 Agent、终端命令与编辑器后台任务。PID 查询无结果不是充分结束证明。本规程要求在禁用启动项后重启本机，并记录重启前后系统启动标识，随后保持宿主及所有相关写入者停止。若存在远端执行、网络共享仓库、无法枚举的后台写入者，规程不适用，继续暂停。

只适用于准备命令的本机标准 Git 操作；不能用重启证明远端 hook 服务、远端执行或另一个主机已停。配置的 post-checkout hook 或自定义派发不能证明安全时继续暂停。

保留 config/marker/journal 配对、新根下该 workflow 的原始字节、原准备记录、诊断与任务历史。使用独立私有备份，保留文件权限；记录备份哈希并回读。不要链接原文件或覆盖旧备份；不回滚 config/state 根目录，不改 Git 文件。

## 2. 允许结算的唯一场景

身份由现有配置、Work Item、规范物理路径、common-dir 和原 preparation 共同约束；全部一致。准备记录必须合法，原 attemptId、完整 baseOid、expectedHead 均可读取。Git 注册唯一绑定目标路径和目标分支，HEAD 等于原 expectedHead，工作树（含未跟踪文件）干净，无进行中的 merge/rebase/cherry-pick/bisect，其他工作区未占用目标分支。配置与工作流固定基线相符，不采用新的 remote tip。

workflow 中不得存在 dev/review 活任务凭据或其它未决 Git/PR 写事务。不能把另一条未决事务搭车清掉。信息缺失、记录损坏、历史迁移配对失败、dirty、HEAD 漂移或身份冲突：继续暂停并保留证据。需要人工 Git 修复的场景另行制定和授权，不附带自动 reset/stash/clean/remove。

满足以上条件只证明“旧本机写入者已结束、当前 Git 结果可被维护者接受”，不证明旧命令的原始返回值，也不恢复旧运行的权限。

## 3. 精确状态变更

维护者制作旧/新 workflow 完整私有文件并核对以下允许差异：

- 将本次 preparation.status 从 dispatched 或 blocked 改为 settled；保留原 attemptId/runtimeInstanceId/baseOid/expectedHead/目标身份。这里是新的人工结算证据，不伪造旧 Shell 返回。
- workflow.revision 和 taskStateRevision 各增加 1，preparation.taskStateRevision 对齐新任务代次。devInterrupted=true，保证普通自动准备不能推进。
- 如有 autoRun，仅设 status=paused、pausedReason=session-interrupted；原 runId、cooldownUsed、halted、计数、deadline、历史与契约全部保留。规程不能补回恢复额度。
- 在现有 events 追加 type=note 的人工结算记录：操作者、时间、attemptId、原状态、新状态、旧文件哈希、私有证据包哈希与结算理由。该事件与状态同次落盘；不新建平行审计数据库。
- updatedAt 更新；其它字段逐项深比较不变。baseRef 不在人工结算时改写，verified 仍由后续正常准备流程在重新授权后生成。

原始输出不放事件；证据包保存在私有目录。原 preparation 在独立备份中保留，不能删除未决历史。

## 4. 写入与中断

只在全部写入者保持停止时执行；离线单操作者独占维护窗口。不在编辑器里直接保存活文件。先将新文件写同目录临时文件并 fsync，再重读旧 workflow、配置配对、Git 现场与证据哈希。任何漂移拒绝，临时文件不生效。匹配时原子 rename，fsync 目录，然后回读目标字节哈希及完整语义差异。备份或事件构造失败，零状态写入。

如中断：保持宿主停止，比较目标字节与已批准的旧/新文件哈希。旧值仍在则只重试原子发布；新值已在则只回读验证；其它值全部拒绝。不得再加一次 revision/event，不重放 Git 写命令。新状态生效后不恢复旧备份（旧授权可能被恢复），后续问题保留暂停、使用新证据处理。

## 5. 重启后

启动宿主应显示暂停，原 autoRun 不自动启动。维护者对原目标和冻结基线重新授权；正常 prepare 只回读 settled 的现场并写 verified，然后 claim 消费准备记录。若 Git/任务事实变化，正常门禁继续拒绝。明确测试：旧任务代次认领失败，旧 autoRun 不能推进，新授权在再次验证后能开始，Git add/switch/remove 写计数为零。

## 6. W2 同步收敛

保留 blocked 的业务语义并实现生产者：在命令已确认结束后的 Git 回读明确不符，或派发前确认存在需人工处理的现场时写 blocked；保留 attemptId 和预期 Git 事实，通过现有 note 事件记录具体安全原因，与状态同次提交。只读查询失败不能伪装成已确认冲突。

命令结束未知仍保留 dispatched，不能被 blocked 覆盖而丢掉未知性质；持久化失败保留上一次状态并报告错误。blocked 的生产消费者是准备入口拒绝自动推进、所有 claim/Git 动作门禁，以及本人工结算规程；它不只是展示字段。人工结算仍只允许 §2 的完整目标现场，其余情况保持暂停。

## 7. 验证和接受门禁

在临时 HOME、真实 Git 仓库中验证：跨 runtime dispatched 拒绝；实际命令写成功后保存前中断；人工结算后新授权只回读而不重放；blocked 的 dirty/冲突保持暂停；旧/新/漂移三种中断结果；未授权差异拒绝；旧 taskStateRevision 认领失败；autoRun 额度不变；新增事件和状态同次落盘。用本地子进程退出及新的 runtime 测流程，不宣称测试证明真实宿主已经重启。

责任：维护者。触发点：#170 发布前完成此规程的接受、文档/验证与 review；现场执行每次另行授权。本 ADR 须按仓库要求合入基线，再经 impl-gate 实现 W2 及验证 W3；当前不把 W2/W3 记为关闭。

已接受的核心变化：允许维护者依据“本机重启后的结束证据 + 精确 Git 回读”离线结算 dispatched/blocked，但永远不自动接管，不清额度，不改 Git，不跳过新授权。

## 8. 算法与数据结构追踪

| 转换 | 读取 | 写入 | 权限与串行化 | 失败结果 |
|---|---|---|---|---|
| 人工准入 | 本机结束证据、配置配对、原 workflow 哈希、原准备记录和 Git 事实 | 私有原/目标文件及证据包 | 维护者；全部写入者停止、单操作者独占维护窗口 | 任一未知或漂移保持暂停，零业务写入 |
| 人工结算 | 已批准旧/新文件、再次核对的现场 | §3 允许差异与 note 事件同次原子发布 | 同一离线维护窗口；只接受精确计划 | 旧/新哈希回读决定重试或完成；其它值拒绝 |
| 新授权准备 | settled、当前任务代次、Git 回读 | verified，后续 claim 消费 | 既有 workflow 持久锁和新授权 | 拒绝旧代次与漂移，不重放 Git 写 |
| 确认异常 | 派发阶段、明确结束证据或派发前现场事实 | blocked 与原因 note 同次提交 | 既有准备事务 | 查询失败不伪造冲突；未知结束保留 dispatched |

| 结构 | 生产者 | 消费者与作用 | 生命周期 |
|---|---|---|---|
| 原/目标 workflow 私有文件及哈希 | 维护者制作、审阅 | 人工授权与发布前漂移检查、中断回读 | 先独立备份，后批准/发布；保留证据，不自动删除 |
| 本机结束证据与 Git 证据包 | 离线维护核查 | 结算准入，哈希写入 note 供审计 | 原始资料保留在私有目录，不能用无记录代替结束证明 |
| preparation.status、任务代次 | 人工结算或既有准备事务 | 准备/claim/Git 动作门禁 | dispatched/blocked→人工 settled→新授权 verified→claim 消费 |
| 既有 events 中的 note | 状态转换同次提交 | 面板历史和维护者审计 | 与 workflow 历史共同保留 |
| autoRun 原额度与 runId | 既有自动运行授权 | 自动恢复与新授权门禁 | 人工规程仅暂停，不重建或清空额度 |

复用既有字段和 note 事件，不增加在线 API、常驻服务或平行审计数据库。版本未知、字段损坏、不能证明记录身份的现场不在本规程内；不得通过新规程降级或重建 state 根目录。
