This baseline is inventory and measurement only. It does not implement Local Git Snapshot, Remote Git Coordinator or GitHub REST Gateway, and it does not change production cache, concurrency, refresh, invalidation or rate-limit behavior.

## Frozen conclusions

1. A hot `/state`-equivalent observation still starts 13 local Git subprocesses per Work Item. The current cache only suppresses GitHub reads; it does not suppress local Git probes.
2. Five concurrently observed Work Items produced 70 subprocesses cold and 60 hot. The cold round took 16.36s because 10 GitHub reads passed through one host-wide serial lane.
3. Three concurrent Review preflights launched three independent `git fetch` operations against the same remote and 12 GitHub REST subprocesses. The item P50 was 21.81s.
4. The code has partial request governance, not the ADR-0007 access planes: repository fetch TTL/singleflight, resource/aggregate REST caches, and a host-wide 250ms REST lane exist; Controller local Git, most Remote Git, direct `gh` writes and all Agent calls remain outside one measurable boundary.
5. Current code does not emit `logicalRequests`, cache hits, singleflight joins, queue wait, invalidation reason, write-readback result or per-response rate-limit consumption. Those values are `unknown`, not zero. Counting `runCommand` calls as any of them would be fake precision.

## Measurement protocol

### Units

| Metric | Frozen meaning |
|---|---|
| `logicalRequests` | One Controller access intent before cache, singleflight or queue policy. A route/scenario invocation is reported separately and is not silently substituted for this value. |
| `physicalSubprocesses` | One host child process. A compound shell is one child even when it executes several Git commands. Pagination and retry children count separately. |
| `upstreamRequests` | One Remote Git operation or one GitHub HTTP request. For current `gh api --include`, one non-retried page equals one child and one HTTP request. Compound remote shells must be decomposed semantically. |
| `cacheHits` | A logical request returned without a new child or upstream request. |
| `singleflightJoins` | A logical request joined an already-running request with the same authoritative scope. |
| `waitMs` | Time from access-boundary entry until physical execution starts. Service time is not queue wait. |
| `failures` | Non-success at logical, child and upstream levels, retaining operation and raw error. Expected probe misses are separately labelled; they are not erased. |
| `invalidations` | Key/scope, reason, triggering action, generation and subsequent observation. Calling `invalidate()` without evidence is not a completed invalidation record. |
| `writeReadbacks` | Write, affected-key invalidation, authoritative reread and equality result. A write response alone is not a readback. |
| `rateLimitConsumption` | Per GitHub resource bucket, response-header or before/after used/remaining/reset delta. Shared-credential snapshots are contaminated unless isolated. |

P50/P95 use nearest-rank on the stated sample set. No interpolation or padded samples are allowed. Fewer than 20 samples must be labelled small-sample; the value is descriptive, not a capacity claim.

### Safety and comparability

- Live GitHub scenarios are read-only. Key writes use a temporary local bare remote; GitHub write latency stays `unknown` because no dedicated test repository was authorized.
- The reproducer anchors all Git checks at the repository root and requires tracked, untracked and ignored `src/` to equal the accepted baseline. `HEAD`, every dirty path and the measurement-tool SHA-256 are recorded separately; the tool may therefore be reviewed without pretending it existed at the accepted runtime SHA.
- Fixture, local real Git, live Remote Git and live GitHub results stay separate. Their latency distributions must never be merged.
- Raw non-zero exits and contaminated rate data remain in evidence. An unavailable metric is `unknown/insufficient`, never zero.
- The scenario harness uses `/bin/zsh -c`, defaults omitted command timeouts to 30s and records the requested sandbox mode, but it does not reproduce the host sandbox wrapper. Count comparisons are authoritative; latency comparisons retain this harness limitation.

## Agent-owned access

### Allowed capabilities in prompts

| Stage | Explicit capability |
|---|---|
| Coding/rework | `git fetch origin`; inspect/update against frozen base; edit/test; commit and push current branch; use `gh` to create/update PR with explicit base. |
| Review | `git fetch origin`; `git diff <base>...HEAD`; read Issue/PR and historical review context with `gh api`; write only the local review-result file. |
| Both | Prefer REST `gh api`, avoid GraphQL aggregations, query a resource once per task unless a write/readback or explicit invalidation requires refresh. |

Allowed capability is not observed usage, and observed usage is not total usage. The blind spots are commands launched inside compound shells, child processes spawned by tools, output lost before persistence, external credential traffic and tasks outside the selected JSONL samples. #122/#131/#135 may supply an ObservationBundle and post-action Controller rereads, but must not claim transparent interception or complete Agent caching.

## Frozen target thresholds

These thresholds are count-first because live latency is noisy and the current samples are small. #122, #131 and #135 must cite this table. Changing a threshold requires a new version, old value, reason and architecture review; moving it to make a PR green is forbidden.

| Scenario | Frozen count / correctness threshold | Frozen latency comparison |
|---|---|---|
| Panel enrichment always on | First observation: Local Git physical ≤1 per Work Item generation; GitHub upstream ≤2 without a linked PR and ≤3 with one. Each unchanged hot poll: Local Git physical =0, Remote Git upstream =0, GitHub upstream =0, expected probe misses =0. Every logical intent must equal hit + join + execution + failure. The separate `/state` fetch gate remains #131 scope. | Hot-only P95 ≤250ms on the same machine; all-round P95 must improve from 5555.85ms and may not regress in cold upstream count. |
| Multi Work Item refresh | Five same-repo items cold: Local Git physical ≤5 and GitHub upstream ≤2 aggregate pages for the measured one-page repo. Immediate hot round: both =0. No host-global queue may serialize unrelated repositories. | Cold round ≤6000ms and hot round ≤250ms on the same environment; compare counts first. |
| Review dense preflight | Three same-repo starts: Remote Git `fetch` upstream ≤1 with two recorded joins; GitHub upstream ≤9; total upstream ≤10. A force request may bypass stale cache but identical safe aggregate reads must still join. | Item P95 ≤15000ms on the same live environment; queue wait and service time must be separately emitted. |
| Key Remote Git write | Exactly one write plus one authoritative readback per successful action; the remote SHA must strictly equal the intended local SHA in 10/10 fixture rounds; cache invalidation occurs before readback result can be consumed. No write may be reported confirmed without equality. | Local bare-remote P95 ≤93ms (20% headroom over 77.18ms, rounded up); live remote latency is a separate series. |
| Key GitHub write | Exactly one write attempt; affected keys invalidated once; exactly one authoritative readback before confirmed success. Failed/unknown writes retain raw response and must not advance workflow. | Baseline and target latency remain `unknown` until a dedicated test repo is authorized; passing by recording zero is forbidden. |
| Rate limit | Every GitHub response records bucket, used/remaining/reset when present. For isolated runs, measured consumption equals actual HTTP pages/retries; contaminated runs are labelled and excluded from hard budget claims. | No numeric latency gate; 429/secondary-limit queueing must fail within the caller budget and expose reset. |

## Reproduction and evidence rules

Run scenarios separately so a long live scenario does not hide status output:

```sh
node scripts/measure-access-baseline.mjs environment
node scripts/measure-access-baseline.mjs panel
node scripts/measure-access-baseline.mjs multi
node scripts/measure-access-baseline.mjs review
node scripts/measure-access-baseline.mjs isolated-write
node scripts/measure-access-baseline.mjs rate
```

The live outputs are expected to vary. Preserve the full JSON output, including commands, non-zero exits, dirty paths and contamination. Do not copy only P50/P95.

The committed evidence has two explicit layers:

- `v0.2-access-baseline-evidence-raw.jsonl`: six complete stdout objects, one per line, with JSON whitespace compacted only.
- `v0.2-access-baseline-evidence.json`: a manually curated navigation summary that points to raw record lines; it is not presented as runner output.

Downstream implementation comparisons may select their own accepted source without editing the script:

```sh
CLICKVIBE_ACCESS_BASELINE_SHA=<candidate-sha> node scripts/measure-access-baseline.mjs <scenario>
```

Existing deterministic evidence remains authoritative for semantics:

```sh
node --test tests/github-rest.test.ts tests/repo-freshness.test.ts tests/state-enrichment.test.ts
node --test tests/routes.test.ts --test-name-pattern='repository GitHub aggregation|repo aggregation consumes|unbounded pagination|share one repository fetch TTL'
node --test tests/access-baseline-script.test.ts
```
